Datasheet Q&A Assistant

Upload an electronics datasheet, ask a question in plain English, and get a short answer with the page number it came from. Built because I got tired of hunting through 16-page PDFs for one number.

View source on GitHub Try the live demo
How it works

Retrieval-augmented generation

The model never sees the whole datasheet blindly. The app finds the pages most likely to hold the answer, and the LLM is told to answer only from them, or say it could not find the answer.

01
Read
Extract each PDF page in layout mode so table columns stay lined up.
02
Search
Combine keyword search with embedding-based semantic search to rank chunks.
03
Ask
Send the best whole pages plus the question to an LLM with a table-reading prompt.
04
Cite
Return a short answer with the page number and the pages used.
Testing

What went wrong, and what I changed

I tested it on the onsemi LM358 datasheet, writing the correct answers myself from the PDF before asking the app. My first version got 8 of 11 questions right. The failures shaped version 2.

  • Wrong column
    Asked for the LM358's typical input offset voltage (2.0 mV), it answered 5.0 mV, which is the LM258's maximum. Flattened table text had lost the column headers. FIX Read pages in layout mode and mark column breaks, so each value stays under its header.
  • Missed table rows
    Pure semantic search sometimes missed the table that held the answer. FIX Hybrid search: keyword scoring plus embeddings, merged by rank, then send whole pages so a row always arrives with its header.
  • Invented a number
    For open-loop gain it once reported "18 dB", taken from a graph's axis labels. FIX The prompt now forbids using graph axis numbers, and says to answer "not found" when the value isn't in the text.

After these changes, the questions that failed now answer correctly, and questions the datasheet cannot answer (price, slew rate, gain-bandwidth) correctly return "not found". I have not yet run the full automated test set on version 2, so I am not quoting a score.

Limits

What it can't do yet

  • Scanned (image-only) PDFs need OCR, which isn't supported.
  • It reads text and tables, not graphs or schematics.
  • The free hosted demo uses keyword search only; the full version also uses semantic search.
  • Visitors supply their own free API key, so my quota stays private.
